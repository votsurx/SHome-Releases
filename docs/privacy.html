Политика конфиденциальности SHome

Версия приложения: 8.6.1
Последнее обновление: 25 Ноября 2026

1. Общие положения

Настоящая Политика конфиденциальности описывает, какие данные собирает, использует и хранит приложение SHome («Приложение»), а также ваши права в отношении этих данных.

Мы не продаём ваши данные третьим лицам.

2. Какие данные мы обрабатываем

2.1. Данные устройств умного дома

  • IP-адреса устройств (Tuya, Zigbee, Frigate)
  • Local Key (ключи шифрования Tuya) — в зашифрованном виде
  • Состояние устройств (вкл/выкл, температура, яркость и т.д.)
  • Названия устройств и комнат
  • DPS-параметры устройств
  • friendly_name Zigbee-устройств

2.2. Данные лицензирования Pro

  • Идентификатор устройства используется приложением локально для привязки лицензии.
  • Отпечаток устройства включается в код запроса, который пользователь может передать разработчику или службе поддержки для выпуска лицензии.
  • Подписанная лицензия и связанные с ней данные хранятся на устройстве. При включённом экспорте лицензия попадает в зашифрованный резервный файл.
  • Дата активации и срок лицензии используются для отображения и проверки лицензии.
  • Дата старта триала и дата последней проверки хранятся локально для учёта пробного периода и защиты от отката системных часов.

Код запроса содержит отпечаток, а не исходный Android ID. Если пользователь передаёт код запроса разработчику или поддержке, полученный в нём отпечаток становится им известен.

2.3. Геолокация (опционально)

SHome использует геолокацию для определения статуса «дома / не дома / рядом» и запуска настроенных автоматизаций. В обычном локальном режиме координаты обрабатываются приложением на устройстве. Если пользователь настраивает отправку координат на свой HTTP endpoint или другой внешний сервис, координаты передаются выбранному им получателю. Не указывайте в запросе адрес разработчика или неизвестного сервиса.

2.4. Данные для уведомлений (опционально)

  • VK-токен и user ID — для отправки уведомлений в VK.
  • Номер телефона — для отправки SMS-уведомлений.

2.5. Данные для облачного резервного копирования (опционально)

  • Логин и пароль Mail.ru Cloud — для загрузки/скачивания зашифрованных бэкапов.
  • Пароль хранится в зашифрованном виде (SecureStorage).

2.6. Технические данные

  • Версия приложения
  • Модель устройства (телефона)
  • Версия операционной системы
  • Логи ошибок (локально, через Talker)

3. Как мы используем данные

  • Для управления устройствами умного дома
  • Для активации и проверки Pro-лицензии
  • Для определения присутствия (если включено)
  • Для отправки уведомлений (если настроено)
  • Для резервного копирования (если настроено)
  • Для исправления ошибок

4. Хранение данных

  • Локальные данные хранятся на устройстве пользователя: настройки и состояние приложения — в локальном хранилище, секреты — в защищённом хранилище платформы.
  • Резервная копия шифруется приложением до загрузки в облако. Для восстановления требуется ключ резервной копии или его QR-код.
  • Лицензия включается в новые резервные копии. При восстановлении на том же устройстве приложение повторно проверяет её подпись и привязку. Старые бэкапы, созданные до добавления лицензии в экспорт, её не содержат.
  • Данные могут передаваться сервисам и устройствам, которые пользователь сам настроил; перечень интеграций приведён ниже.

5. Сторонние сервисы

Приложение может взаимодействовать со следующими сторонними сервисами по вашему выбору:

5.1. Tuya (умные устройства)

  • Что передаётся: идентификатор устройства, IP-адрес, статус.
  • Куда: локально (LAN) или через Tuya Cloud (если настроено).
  • Политика: https://www.tuya.com/privacy

5.2. Zigbee2MQTT (Zigbee-устройства)

  • Что передаётся: MQTT-сообщения с состоянием устройств.
  • Куда: ваш MQTT-брокер (локально или удалённо).
  • Политика: зависит от вашего брокера.

5.3. Frigate (видеонаблюдение)

  • Что передаётся: события детекции (person, car), статистика.
  • Куда: ваш сервер Frigate (локально или удалённо).
  • Политика: зависит от вашего сервера.

5.4. Mail.ru Cloud (резервное копирование)

  • Что передаётся: зашифрованный файл конфигурации.
  • Куда: Mail.ru Cloud.
  • Политика: https://help.mail.ru/cloud/legal/privacy

5.5. VK (уведомления)

  • Что передаётся: текст уведомления, ваш VK user ID.
  • Куда: VK API.
  • Политика: https://vk.com/privacy

5.6. SMS-шлюз (уведомления)

  • Что передаётся: текст SMS, номер телефона.
  • Куда: через SMS-шлюз вашего оператора.
  • Политика: зависит от оператора.

5.7. GitHub (обновления)

  • Что передаётся: версия приложения (для проверки обновлений).
  • Куда: GitHub API.
  • Политика: https://docs.github.com/en/site-policy/privacy-policies

6. Безопасность

  • Шифрование данных (AES-256, SecureStorage)
  • Безопасные протоколы передачи (HTTPS, MQTT over TLS — если настроено)
  • Регулярные обновления безопасности
  • Локальное хранение (без облачных сервисов разработчика)

7. Аналитика и логи

В приложении не настроены Firebase Analytics и Crashlytics. Логи приложения хранятся локально. Они могут быть переданы разработчику, если пользователь самостоятельно отправит их вместе с обращением в поддержку.

8. Права пользователя

  • Получить копию своих данных с помощью экспорта конфигурации в настройках.
  • Удалить локальные данные средствами Android. Удаление приложения обычно удаляет его локальные данные; резервные копии в облаке нужно удалять отдельно.
  • Отключить геолокацию, уведомления и облачные функции в настройках приложения.
  • Обратиться с вопросом или жалобой в Роскомнадзор (https://rkn.gov.ru).

9. Данные детей

Приложение не предназначено для детей младше 13 лет. Мы сознательно не собираем данные детей.

10. Обработка данных и управление настройками

SHome обрабатывает данные, необходимые для работы выбранных пользователем функций. Необязательные функции можно не включать; доступ к геолокации регулируется также разрешениями Android.

  • Идентификатор устройства: используется локально для лицензирования Pro. При запросе лицензии приложение формирует код с отпечатком устройства. Этот код передаётся разработчику или поддержке только по решению пользователя, например при отправке обращения.
  • Геолокация: обрабатывается, если включена функция присутствия и предоставлено разрешение Android. Если пользователь настроил отправку координат на внешний endpoint, они передаются указанному получателю.
  • Данные облака и резервной копии: используются при настройке облачного резервного копирования. Резервная копия шифруется приложением; для её восстановления нужен ключ резервной копии или QR-код.
  • VK-токен, номер телефона и данные устройств: используются соответствующими функциями при их настройке и обращении к выбранным пользователем сервисам.

Пользователь может отключить необязательные функции и отозвать разрешения Android в настройках приложения или системы. Удаление приложения обычно удаляет локальные данные приложения, но резервные копии, ранее загруженные в облако, нужно удалять отдельно. Переданные внешним сервисам данные обрабатываются также по правилам этих сервисов.

11. Изменения политики

Мы можем обновлять политику. О значительных изменениях будем уведомлять в приложении. Дата последнего обновления указана в начале документа.

SHome Privacy Policy

App version: 8.6.1
Last updated: November 25, 2026

1. General

This Privacy Policy describes what data the SHome application (the “App”) collects, uses, and stores, as well as your rights regarding this data.

We do not sell your data to third parties.

2. Data we process

2.1. Smart home device data

  • Device IP addresses (Tuya, Zigbee, Frigate)
  • Local Keys (Tuya encryption keys) — encrypted
  • Device state (on/off, temperature, brightness, etc.)
  • Device and room names
  • Device DPS parameters
  • Zigbee device friendly_name

2.2. Pro licensing data

  • Device identifier is used locally by the App for license binding.
  • Device fingerprint is included in a license request code that the user may choose to send to the developer or support team to request a license.
  • Signed license and related data are stored on the device. When included in an export, the license is part of the encrypted backup file.
  • License activation date and expiry are used to display and validate the license.
  • Trial start date and last-seen date are stored locally to track the trial period and help detect system clock rollback.

The license request code contains a device fingerprint, not the original Android ID. If the user sends the request code to the developer or support team, they will be able to see the fingerprint contained in it.

2.3. Geolocation (optional)

  • Device coordinates (latitude and longitude) are processed when the user enables the “Presence” feature and grants the required Android permission.
  • Home radius is set by the user.

SHome uses geolocation to determine “home / away / nearby” status and to trigger configured automations. In the normal local mode, the App processes coordinates on the device. If the user configures coordinates to be sent to an HTTP endpoint or another external service, they are sent to the recipient selected by the user. Do not configure an unknown service or an endpoint controlled by the developer.

2.4. Notification data (optional)

  • VK token and user ID — to send VK notifications.
  • Phone number — to send SMS notifications.

2.5. Cloud backup data (optional)

  • Mail.ru Cloud login and password — to upload/download encrypted backups.
  • Password is stored encrypted (SecureStorage).

2.6. Technical data

  • App version
  • Device model
  • Operating system version
  • Error logs (locally, via Talker)

3. How we use data

  • To control smart home devices
  • To activate and verify the Pro license
  • To determine presence (if enabled)
  • To send notifications (if configured)
  • To perform backups (if configured)
  • To fix errors

4. Data storage

  • Local data is stored on the user's device. App settings and data are stored locally; secrets use the platform's secure storage.
  • Backups are encrypted by the App before upload to cloud storage. A backup key or its QR code is required to restore a backup.
  • License data is included in new backups. When restored on the same device, the App rechecks the license signature and device binding. Backups created before license data was added to exports do not contain the license.
  • Data may be sent to devices and services that the user has configured. See Section 5 for the integrations described in this policy.

5. Third-party services

The App may interact with the following third-party services at your choice:

5.1. Tuya (smart devices)

  • Data transmitted: device ID, IP address, status.
  • Destination: locally (LAN) or via Tuya Cloud (if configured).
  • Policy: https://www.tuya.com/privacy

5.2. Zigbee2MQTT (Zigbee devices)

  • Data transmitted: MQTT messages with device state.
  • Destination: your MQTT broker (local or remote).
  • Policy: depends on your broker.

5.3. Frigate (video surveillance)

  • Data transmitted: detection events (person, car), statistics.
  • Destination: your Frigate server (local or remote).
  • Policy: depends on your server.

5.4. Mail.ru Cloud (backup)

  • Data transmitted: encrypted configuration file.
  • Destination: Mail.ru Cloud.
  • Policy: https://help.mail.ru/cloud/legal/privacy

5.5. VK (notifications)

  • Data transmitted: notification text, your VK user ID.
  • Destination: VK API.
  • Policy: https://vk.com/privacy

5.6. SMS gateway (notifications)

  • Data transmitted: SMS text, phone number.
  • Destination: via your carrier's SMS gateway.
  • Policy: depends on the carrier.

5.7. GitHub (updates)

  • Data transmitted: app version (to check for updates).
  • Destination: GitHub API.
  • Policy: https://docs.github.com/en/site-policy/privacy-policies

6. Security

  • Secrets are stored using the platform's secure storage.
  • Cloud backups are encrypted by the App before upload using AES-256-GCM.
  • HTTPS and MQTT over TLS can be used where supported and configured.
  • Security also depends on the user's device, operating system, network and third-party service configuration.

7. Analytics and error logs

The App does not use Firebase Analytics, Crashlytics or other external analytics services. App logs are stored locally. They may be shared with the developer if the user chooses to include them in a support request.

8. User rights

  • Obtain a copy of your data by exporting the configuration in the App settings.
  • Delete local data using Android settings. Uninstalling the App usually removes its local data; cloud backups must be deleted separately.
  • Disable geolocation, notifications and cloud features in the App or Android settings.
  • Contact Roskomnadzor with a complaint (https://rkn.gov.ru).

9. Children's data

The App is not intended for children under 13. We do not knowingly collect children's data.

10. Data processing and settings

SHome processes data needed for the features selected by the user. Optional features do not need to be enabled. Access to geolocation is also controlled by Android permissions.

  • Device identifier: used locally for Pro licensing. When a license is requested, the App creates a request code containing a device fingerprint. The user decides whether to send that code to the developer or support team, for example as part of a support request.
  • Geolocation: processed when Presence is enabled and Android permission is granted. If the user configures an external endpoint, coordinates are sent to the specified recipient.
  • Cloud and backup data: used when cloud backup is configured. The App encrypts backups before upload. A backup key or its QR code is required for restoration.
  • VK token, phone number and device data: used by the corresponding features when configured and when communicating with services selected by the user.

Users can disable optional features and revoke Android permissions in the App or system settings. Uninstalling the App usually removes its local data, but backups already uploaded to cloud storage must be deleted separately. Data sent to external services is also subject to those services' own policies.

11. Changes to this policy

We may update this policy. We will notify users in the App about significant changes. The last updated date is shown at the beginning of this document.

12. Contact

For privacy questions, contact: votsurx@gmail.com
