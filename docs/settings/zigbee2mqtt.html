Настройка Zigbee2MQTT (Z2M)

SHome поддерживает Zigbee-устройства через Zigbee2MQTT (Z2M). Z2M — это мост между Zigbee-координатором и MQTT-брокером. SHome подключается к MQTT и получает список устройств.

Схема: Zigbee-устройство → Zigbee-координатор → Z2M → MQTT-брокер → SHome

Что нужно

  • Zigbee-координатор: CC2652, ConBee II, Sonoff Zigbee 3.0, SkyConnect и т.п.
  • Сервер: Raspberry Pi 4+, Intel NUC, Synology, мини-ПК.
  • MQTT-брокер: Mosquitto (рекомендую).
  • Docker (опционально, но проще).

Шаг 1. Установить MQTT-брокер (Mosquitto)

Если у вас ещё нет MQTT-брокера — установите Mosquitto:

docker run -d \
  --name mosquitto \
  --restart=unless-stopped \
  -p 1883:1883 \
  -p 9001:9001 \
  -v /path/to/mosquitto.conf:/mosquitto/config/mosquitto.conf \
  -v /path/to/mosquitto/data:/mosquitto/data \
  eclipse-mosquitto

Минимальный mosquitto.conf:

listener 1883
allow_anonymous false
password_file /mosquitto/data/passwd

Создайте пользователя:

docker exec -it mosquitto mosquitto_passwd -c /mosquitto/data/passwd your_user

Шаг 2. Установить Zigbee2MQTT

Docker (рекомендую)

docker run -d \
  --name zigbee2mqtt \
  --restart=unless-stopped \
  -p 8080:8080 \
  -v /path/to/zigbee2mqtt/data:/app/data \
  --device=/dev/ttyUSB0 \
  koenkk/zigbee2mqtt

Порт /dev/ttyUSB0 — путь к Zigbee-координатору. На Linux обычно /dev/ttyUSB0 или /dev/ttyACM0. Проверьте:

ls /dev/ttyUSB* /dev/ttyACM*

На Windows — COM3 и т.п. (но Z2M лучше ставить на Linux/Raspberry Pi).

Или по официальной инструкции

https://www.zigbee2mqtt.io/guide/installation/

Шаг 3. Настроить configuration.yaml

Файл: /path/to/zigbee2mqtt/data/configuration.yaml:

mqtt:
  server: mqtt://your-mqtt-broker:1883
  user: your_user
  password: your_password

serial:
  port: /dev/ttyUSB0
  adapter: zstack  # или deconz, ezsp и т.п.

frontend:
  port: 8080

homeassistant: false  # SHome не требует Home Assistant

permit_join: false  # включайте вручную при сопряжении

advanced:
  network_key: GENERATE  # или ваш ключ

adapter — тип координатора:

  • zstack — CC2652, CC2531, Sonoff Zigbee 3.0
  • deconz — ConBee II
  • ezsp — SkyConnect, EFR32

Шаг 4. Запустить Z2M

docker restart zigbee2mqtt

Проверьте логи:

docker logs -f zigbee2mqtt

Должно быть:

Zigbee2MQTT started!
MQTT connected
Coordinator: CC2652P (firmware 20220219)

Откройте веб-интерфейс: http://your-server:8080.

Шаг 5. Сопрячь Zigbee-устройства

  1. В Z2M: Permit join (all) → включите (или permit_join: true в конфиге).
  2. Переведите Zigbee-устройство в режим сопряжения (обычно: удерживайте кнопку 5–10 сек).
  3. В Z2M появится новое устройство. Дайте ему имя (например, living_room_lamp).
  4. Выключите Permit join.

Шаг 6. Настроить SHome

  1. Откройте SHome → Настройки → MQTT.
  2. Введите:
    • URL: mqtt://your-mqtt-broker:1883
    • Логин: your_user
    • Пароль: your_password
  3. Сохраните. SHome подключится к брокеру.
  4. Откройте Меню → Zigbee → «Сканировать».
  5. SHome получит список устройств из Z2M. Добавьте нужные на главный экран.

Шаг 7. Проверить

  • В SHome: меню → Zigbee → список устройств.
  • Добавьте устройство на главный экран (вкл/выкл, яркость и т.д.).
  • Проверьте управление.

Частые проблемы

Z2M не подключается к MQTT

  • Проверьте mqtt.server, user, password в configuration.yaml.
  • Проверьте, что MQTT-брокер запущен (docker ps).
  • Проверьте firewall (порт 1883).

Z2M не видит координатор

  • Проверьте /dev/ttyUSB0 (или /dev/ttyACM0).
  • Права доступа: sudo usermod -a -G dialout $USER, перезагрузка.
  • Проверьте, что координатор не занят другим процессом.

SHome не видит Z2M

  • Проверьте MQTT-настройки в SHome (URL, логин, пароль).
  • Проверьте, что Z2M публикует топики: zigbee2mqtt/bridge/devices.
  • Проверьте firewall между SHome (телефон) и MQTT-брокером.

Устройства не сопрягаются

  • Permit join включён?
  • Устройство в режиме сопряжения? (см. инструкцию устройства)
  • Устройство рядом с координатором (для сопряжения).
  • Проверьте логи Z2M: docker logs -f zigbee2mqtt.

«Network key» ошибка

  • При первом запуске Z2M генерирует network_key. Если меняли — все устройства нужно сопрячь заново.
  • Сохраните network_key в надёжном месте.
